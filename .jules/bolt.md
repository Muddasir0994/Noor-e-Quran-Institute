## 2024-10-08 - Optimized DataStore File Writes and Graceful Shutdown
**Learning:** The `DataStore` singleton relied on synchronous file writes (`fs.writeFileSync`) which blocks the event loop on every mutation, degrading performance severely under concurrent API loads (e.g. `test_perf_concurrent.cjs` taking significantly longer due to file I/O blocking the main thread). A naive switch to async writes without a concurrency lock risks data loss or out-of-order writes during high-frequency saves.
**Action:** Always implement async I/O in singletons with a concurrency queue/lock (e.g., using `while (this.pendingData)`). Additionally, stateful backends maintaining critical write locks require explicit graceful shutdown handling (`SIGTERM`/`SIGINT`) to reject new requests and await flushing of any queued promises to prevent database corruption.
