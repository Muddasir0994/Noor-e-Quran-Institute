## 2024-06-15 - Optimizing Synchronous File Writes

**Learning:** `DataStore` singleton implementations often use synchronous `fs.writeFileSync` methods for simplicity which block the main node thread causing major performance bottlenecks, especially under concurrent load. Converting these to asynchronous `fs.promises.writeFile` calls can significantly speed up response times. However, since node is single threaded, simply making them async without a queue can result in overlapping writes and data loss. We must implement a concurrency lock/queue loop (e.g. `while(this.pendingData)`) to prevent this. Furthermore, async file operations on backend singletons require graceful server shutdowns using `server.closeAllConnections()`, `server.close()`, and awaiting a `flush()` function, to guarantee writes complete before the node process exits.

**Action:** Whenever identifying `fs.writeFileSync` in a high-traffic node service like a singleton db store, carefully convert it to async. Ensure to implement a concurrency queue loop, assigning `this.pendingData = dataToSave || this.data`, and add strict graceful shutdown logic in the server setup to flush queued promises to avoid data loss.
