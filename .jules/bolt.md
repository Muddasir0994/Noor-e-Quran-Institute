## 2025-02-27 - Optimize File Write Concurrency in Backend DataStore
**Learning:** The `DataStore` backend singleton used a fully synchronous `fs.writeFileSync` in `saveDatabase` upon every single data modification. In a Node.js event-driven system, blocking synchronous file writes on a single main thread can severely stall the event loop under load, delaying all concurrent Express incoming requests and slowing down overall backend TTFB (Time to First Byte). Replacing it with a naive async `fs.promises.writeFile` without queuing mechanism could result in data-loss and file corruption if concurrent saves happen simultaneously.
**Action:** Implement an asynchronous write concurrency queue loop. Use `while(this.pendingData)` to drain sequential states dynamically without data loss from overlaps. Combined with hooking `dataStore.flush()` into Node's graceful exit events (`SIGINT`/`SIGTERM`), you can guarantee process shutdowns do not abruptly cancel chained Promises waiting in the event loop queue, guaranteeing data safety alongside unblocked performance.
