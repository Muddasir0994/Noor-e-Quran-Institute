## 2024-06-12 - File I/O Optimization in Singletons
**Learning:** Found a performance bottleneck specific to this codebase where the `DataStore` singleton blocked the Node.js event loop due to synchronous `fs.writeFileSync`. This caused main-thread pausing across the entire Express API for every database modification, significantly degrading scalability under load. A simple `fs.promises.writeFile` wasn't enough; concurrent asynchronous calls to the same file caused data corruption. We had to implement an async write queue (locking with `pendingData`) combined with a robust graceful shutdown (`server.closeAllConnections()` + `flush()` on `SIGINT`) to ensure no data loss during dynamic queue processing.
**Action:** Next time synchronous file operations are found in backend singletons, check if they are mutating shared data. If converting to async, immediately evaluate concurrency locks (to prevent file corruption) and check if the application's shutdown logic needs to be patched to await remaining operations.
