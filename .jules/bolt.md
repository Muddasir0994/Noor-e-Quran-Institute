## 2024-05-24 - Synchronous File I/O Bottlenecks and Queue Management
**Learning:** In a heavily concurrent Node.js/Express environment, replacing synchronous file writes (`fs.writeFileSync`) with asynchronous ones (`fs.promises.writeFile`) without a queue mechanism can lead to race conditions where older data overwrites newer data. However, implementing a standard boolean lock (`if (isWriting) return`) causes data loss because incoming data requests during a lock are completely discarded.
**Action:** When optimizing synchronous file writes in singletons (like DataStore), use a `while(this.pendingData)` loop for concurrency to queue overlapping writes. Always assign the latest payload to the queue cache *outside* the async lock so rapid, concurrent saves pick up the latest state without skipping writes or blocking the main thread.
