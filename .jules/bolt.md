## 2024-10-23 - Prevent concurrent `fs.writeFileSync` overlapping writes from losing data
**Learning:** The `dataStore.ts` implementation of `saveDatabase` used synchronous `fs.writeFileSync(DB_FILE, ...)` when persisting database changes. Since NodeJS is asynchronous, multiple API requests updating the database sequentially but concurrently could trigger simultaneous calls to `fs.writeFileSync`, causing data corruption or overlapping saves because `saveDatabase` does not queue writes. Also it slows down request processing.
**Action:** When saving singleton database cache states to disk in Express routes, use an asynchronous queue loop (e.g. `while (this.pendingData)`) with `fs.promises.writeFile` to guarantee sequential disk writes without blocking the main event loop and without dropping rapid subsequent updates.
