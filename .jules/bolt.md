## 2025-03-08 - Synchronous Disk I/O Blocking and Graceful Shutdown
**Learning:** Using `fs.writeFileSync` in a Node.js singleton (`DataStore`) heavily blocks the Express main event loop, causing severe latency spikes during concurrent database updates (e.g., test or user surges). Furthermore, converting it directly to `fs.promises.writeFile` without a concurrency queue/lock leads to file corruption if concurrent saves happen. Finally, removing synchronous writes means we MUST have a graceful shutdown handler attached to `SIGTERM`/`SIGINT` that correctly rejects new connections and explicitly `awaits` the flush of queued file writes inside the `server.close` callback, or data will be dropped mid-write on restart/deploy.
**Action:** Always wrap `fs.promises.writeFile` in a queue or lock (e.g., `isWriting` / `pendingWrite` loop), implement a `flush()` loop to wait for those promises, and integrate that `flush()` directly into the main application's `server.close` graceful shutdown logic, complete with a timeout fallback.
