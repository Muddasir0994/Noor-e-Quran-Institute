## 2025-03-09 - Prevent Stored XSS in React Using DOMPurify
**Vulnerability:** The `BlogPostPage.tsx` and `BlogEditor.tsx` rendered user-supplied rich text using `dangerouslySetInnerHTML` directly or `{post.content}` which outputs text. If a user was able to inject HTML, they could achieve stored XSS.
**Learning:** In React applications, data from WYSIWYG editors or other rich text input fields can contain HTML formatting which is dangerous to reflect directly. Unsanitized `dangerouslySetInnerHTML` is an immediate vector for DOM-based or stored XSS vulnerabilities. React's default `{content}` rendering escapes HTML, breaking the display formatting.
**Prevention:** To safely render rich text formatted with HTML in React, you must use `dangerouslySetInnerHTML` together with a sanitizer like `DOMPurify`. The pattern must always be `dangerouslySetInnerHTML={{ __html: DOMPurify.sanitize(content) }}`. Also remember to use standard HTML `class` attribute strings in fallback placeholders because `DOMPurify` parses standard HTML and strips React `className` properties.
